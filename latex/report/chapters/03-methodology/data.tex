All the data are in plain CSV files under \texttt{code/data/}:
\begin{itemize}
  \item \texttt{locations.csv}: the vertices (Table~\ref{tab:vertices});
  \item \texttt{distance\_matrix\_km.csv}: the edge weights (Table~\ref{tab:matrix});
  \item \texttt{raw\_directed\_km.csv}: the raw directed distances, before averaging.
\end{itemize}
The program reads these files directly, and every table
and figure in this report is generated from the same run of the program, so the graph, the data, the
program input and the reported results are consistent. The OSRM request was retrieved in October 2026;
the committed CSV files are the dataset of record, since the public demo service and its OpenStreetMap
data can change over time.

\paragraph{Cross-check with Google Maps.}
Table~\ref{tab:gmaps} compares each leg of the final route with the driving
distance shown by separate Google Maps searches for each leg in driving mode, in route order.
The Google values are rounded to the nearest 0.05--0.10 km as displayed by
the searches. The two sources
agree on the whole tour within 4.2\%, but individual legs differ by up to
39\%. Possible reasons are different pin positions, one-way streets, and
different road choices and turn restrictions. Both readings were made in driving mode, but Google Maps
and OSRM independently select routes using different map data and routing rules. We keep the OSRM matrix as the dataset because it is
reproducible and is read directly by the program.
